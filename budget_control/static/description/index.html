Budget Control

This module is the main module from a set of budget control modules. This module alone will allow you to work in full cycle of budget control process. Other modules, each one are the small enhancement of this module, to fullfill additional needs. Having said that, following will describe the full cycle of budget control already provided by this module,

Budget Control Core Features:

  • Budget Commitment (base.budget.move)

    Probably the most crucial part of budget_control.

    • Budget Balance = Budget Allocated - (Budget Actuals - Budget Commitments)

    Actual amount are from account.move.line from posted invoice. Commitments can be sales/purchase, expense, purchase request, etc. Document required to be budget commitment can extend base.budget.move. For example, the module budget_control_expense will create budget commitment expense.budget.move for approved expense. Note that, in this budget_control module, there is no extension for budget commitment yet.

    Budget moves and the Budget Monitoring report have one column (x_plan<id>_id) per root analytic plan without Control Budget, created with the plan, holding the other analytic accounts of the distribution row the move comes from; the account of a controlled plan is the move’s Analytic Account. Commitment forward lines have the same columns. A module that adds a budget move model calls account.analytic.plan._sync_budget_columns from its data, as data/analytic_plan_data.xml does. Moves created before a plan existed have an empty column; recompute the document to fill it.

  • Budget Template (budget.template)

    A Budget Template in the budget control system serves as a framework for controlling the budget, allowing for the budget to be managed according to the pre-defined template. The budget template has a relationship with the accounting, and is used to control spending based on pre-configured accounts.

  • Budget Period (budget.period)

    Budget Period is the first thing to do for new budget year, and is used to govern how budget will be controlled over the defined date range, i.e.,

    • Duration of budget year
    • Template to control (budget.template)
    • Document to do budget checking
    • Analytic account in controlled
    • Control Level

    Although not mandatory, an organization will most likely use a fiscal year as its normal budget period. A Lifetime analytic, such as a campaign, grant, or one-off initiative, may instead use one dedicated multi-year period. Because that period is scoped to one analytic account, it may overlap the organization’s fiscal periods without making document-period selection ambiguous.

  • Budget Control Sheet (budget.control)

    Each fiscal analytic account can have one budget control sheet per budget period. A Lifetime analytic has one sheet for its dedicated period. The budget control is used to allocate budget amount in a simpler way. In the backend it simply create budget.control.line, nothing too fancy. Once we have budget allocations, the system is ready to perform budget check.

    Sheets are created directly, or from a Budget Plan with the module budget_plan.

  • Budget Checking

    By calling function – check_budget(), system will check whether the confirmation of such document can result in negative budget balance. If so, it throw error message. In this module, budget check occur during posting of invoice and journal entry. To check budget also on more documents, do install budget_control_xxx relevant to that document.

  • Budget Constraint

    To make the function – check_budget() more flexible, additional rules or limitations can be added to the budget checking process. The system will perform the regular budget check and will also check the additional conditions specified in the added rules. An example of using budget constraints can be seen from the budget_allocation module.

  • Budget Reports

    Currently there are 2 types of report.

    1. Budget Monitoring: combine all budget related transactions, and show them in Standard Odoo BI view.
    2. Actual Budget Moves: combine all actual commit transactions, and show them in Standard Odoo BI view.

  • Budget Commitment Move Forward

    In case budget commitment is being used. Sometime user has committed budget withing this year but not ready to use it and want to move the commitment amount to next year budget. Budget Commitment Forward can be use to change the budget move’s date to the designated year, on the analytic each analytic continues as: itself for an analytic used for years, or the next analytic of a yearly one (Continues As).

  • Budget Transfer

    This module allow transferring allocated budget from one budget control sheet to other

  • Budget Balance Forward

    Active controls from a Fiscal Period are proposed in the audited Forward Budget Balance document. A budget manager reviews the analytics and amounts before posting them to the next Fiscal Period, on the analytic each continues as. Once the commitments are forwarded, the balance carries their budget too. Lifetime periods already span their complete duration and cannot use carry forward.

Usage

Before start using this module, following access right must be set.

  • Budget User for Budget Control Sheet, Budget Report
  • Budget Manager for Budget Period

Followings are sample steps to start with,

  1. Set up the analytic plans

    • Keep Control Budget ticked on the root plans whose accounts own budgets (e.g. Departments, Projects) and untick it on plans used for reporting only (e.g. Fund).
    • One row of an analytic distribution can hold only one account of a controlled plan, and one account of each plan. To charge two budgets, split the line into rows by percentage. The same account may be in several rows, e.g. Department 1 / Fund A 60% and Department 1 / Fund B 40%: each row commits its own part.
    • Budget moves and the Budget Monitoring report get one column per root plan without Control Budget, so they can be grouped by it, e.g. by Fund. The account of a controlled plan is the Analytic Account of the move. Control Budget cannot change once budget moves use the plan.
    • Budgets follow the company of their analytic account, as in Odoo: an analytic account without company can be used by every company, one with a company by that company and its branches. To share a budget between some companies only, use an analytic account without company and set the Allowed Companies of its budget control sheet; documents of other companies cannot consume it.

  2. Create new Budget KPI

    To create budget KPI using in budget template

  3. Create new Budget Template

    • Add new template for controlling Budget following kpi-account

  4. Create new Budget Period

    • Choose Budget template
    • Identify date range, i.e., 1 fiscal year
    • Plan Date Range, i.e., Quarter, the slot to fill allocation in budget control will split by quarter
    • Control Budget = True (if not check = not check budget for this period)

    Normal periods use the Fiscal Period scope. Lifetime periods are restricted to one analytic account and may overlap fiscal periods safely.

  5. Create Budget Control Sheet

    Menu > Budgeting > Budget Control Sheet, create one sheet per analytic account and budget period, with its Allocated amount. Its name and Plan Date Range come from the period. Choose its KPIs and click Soft Reset to create the plan table.

    With the module budget_plan, sheets are created from a Budget Plan instead, which then manages their Allocated amount.

  6. Allocate amount in Budget Control Sheets

    Each analytic account will have its own sheet. Form Budget Period, click on the icon “Budget Control Sheets” or by Menu > Budgeting > Budget Control Sheet, to open them.

    • Based on “Plan Date Range” period, Plan table will show all KPI split by Plan Date Range
    • Allocate budget amount as appropriate.
    • Click Control button, state will change to Controlled.

    Note: Make sure the Plan Date Rang period already has date ranges that covers entire budget period. Once ready, you can click on “Reset Plan” anytime.

  7. Budget Reports

    After some document transaction (i.e., invoice for actuals), you can view report anytime.

    • On Budget Control sheet, click on Monitoring for see this budget report
    • Menu Budgeting > Budget Monitoring, to show budget report in standard Odoo BI view.

  8. Budget Checking

    As we have checked Control Budget = True in third step, checking will occur every time an invoice is validated. You can test by validate invoice with big amount to exceed.

  9. Create a Lifetime budget without a Project

    • Open the Analytic Account and click Create Lifetime Budget.
    • Enter the fixed Start Date, End Date, Budget Template, planning range, and Total Budget.
    • Ensure the selected planning range has Date Ranges covering the complete Lifetime duration. The setup stops without creating partial records when a range is missing.
    • The system creates one dedicated Lifetime Period and one draft Budget Control. Distribute the total on its control lines, then submit and control it normally.

    Lifetime is suitable for a campaign, grant, contract, or other one-off initiative that can span several fiscal years. It does not use a Budget Plan or carry forward. Lifetime analytics are therefore excluded from Fiscal Budget Plan allocation, including the Refresh and Get All Analytic Accounts actions; allocate them directly on their dedicated Budget Control instead.

  10. Close a year: carry commitments and balances to the next period

    An analytic is used in one of two ways:

    • Continuing: the same analytic for years, without Budget Period. It continues as itself while it is open: leave its Date To empty, or extend it. Each period has its own Budget Control Sheet for it.
    • Yearly: a new analytic each period, with that Budget Period. It continues as the analytic in its Continues As field, an analytic of the next period.

    Continue in Budget Period, from the analytics list (Action) or the forwards (Continue Analytics), proposes it for the analytics that do not continue yet: it extends continuing analytics that end before the period, links yearly ones to the only analytic of the period with the same name, code, root plan and company, or creates their copy for the period. Choose the analytic when several match.

    Then:

    • Forward Budget Commitment carries the open commitments to the period, on the analytic each continues as (editable by line, e.g. to carry some documents elsewhere) and their Forward Dimensions. A commitment not used in that period is carried again by the next one.
    • Forward Budget Balance carries the available balance of each analytic, after the commitments are forwarded: their budget comes with them. Its preview warns of commitments still in the period. Adjust the amounts or remove lines that must lapse before completing the forward.
    • Create the target-period Budget Plan. It takes the yearly analytics of the period and the continuing ones budgeted the period before, and its Forward Balance is included in the amount available for the new Budget Control Sheet.

    Lifetime analytics are not carried forward: their commitments and balance remain available for their complete duration.

Development

Extension modules, e.g. budgets of purchases or expenses, build on these hooks.

Document lines inherit budget.docline.mixin and set _budget_move_model, _doc_rel and _budget_date_commit_fields (_budget_analytic_field is analytic_distribution by default).

  • A row of the analytic distribution commits one budget analytic, an account of a plan with Control Budget, with its full percentage. In _init_docline_budget_vals(budget_vals, analytic_id), take the percentage of the row being committed from _get_budget_analytic_percent(analytic_id), not from distribution[str(analytic_id)].
  • amount_commit is keyed by row, budget_row_key() of odoo.addons.budget_control.models.analytic_plan, and return_amount_commit in context may be such a dict.
  • commit_budget() creates one budget move per row and calls _update_template_line(budget_move) for each.
  • recompute_budget_move_batch(), used by journal items and budget adjustments, and the batch precommit of models whose _can_batch_budget_precommit() is true, do not call commit_budget(): extend _prepare_commit_vals() or _init_docline_budget_vals().
  • _get_budget_company() is the company of the document, whose budget settings apply: use it in _get_included_tax().

Budget move models inherit base.budget.move. Their plan columns x_plan<id>_id, one per root plan without Control Budget, are created by account.analytic.plan._sync_budget_columns(): call it from the data of the module, as data/analytic_plan_data.xml does.

Budget check (budget.period):

  • _get_control_budget_moves(budget_period, doclines) selects the budget moves a period checks, and _prepare_controls() their controls.
  • _get_where_domain(analytic_id, template_lines) returns an SQL object. Extensions adding filters to it also override _can_use_budget_available_cache() to return False for them.
  • _get_analytic_budget_control(analytic, date_commit, company) of document lines gives the budget control sheet; its currency_id replaces _get_analytic_budget_currency().
  • Budget Constraints run a server action with doclines in context, whose action is the list of error messages.

Continuation: account.analytic.account._get_forward_analytic(period) gives the analytic the budgets and commitments of an analytic are carried forward to in a period: itself when _is_forward_target(period) (fiscal, of a plan with Control Budget, of that period or without Budget Period, open when it starts), else along next_analytic_id; none for Lifetime analytics. The budget.analytic.continue wizard extends (_extend_budget_analytic()), links (_get_next_analytic_matches()) or creates (_prepare_next_analytic_vals()) them, and _get_continue_action(period, analytics) opens it. Commitment and balance forward lines default their forward analytic to it.

Commitment forwards carry each analytic row to the forward analytic and the Forward Dimensions of its line (to_dimension_ids, those of the row by default): _get_target_row_key() and _get_target_column_vals() give the target row, _get_budget_row_key() the source row. On document lines, _get_budget_forward_date() and _get_budget_rows_at(date) give where the done forwards carried the commitment, e.g. to check the rows of a bill. Before anything changes, _check_forward_targets() refuses the lines _get_target_error() returns a message for, e.g. when the target row fails _check_budget_forward_row(row_key) of the document line: the check of its own _validate_analytic_distribution(), such as its mandatory plans. Rows of Lifetime analytics are not forwarded, and budget.commit.forward.line._get_commit_forward_in_map(period_ids, analytic_ids) sums the commitments the done forwards carried in.

Monitoring (budget.monitor.report): its query is _table_sql. A source of consumption is added to _get_consumed_sources(), and its branch to _get_sql_branches() with _get_consumed_sql(amount_type, where), instead of appending SQL text to _get_sql(). Branches without plan columns select _select_plan_columns_null(). The monitoring shows the amount types in the order of their keys, e.g. 30_po_commit before 80_actual: a commitment takes a key before 80_.
